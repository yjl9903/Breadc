# 编码规范

## 语言与接口

使用 strict TypeScript 和 ESM，公开 API 优先使用命名导出。相对 TypeScript 导入沿用当前项目的 `.ts` 扩展名，跨包使用包名。

公开入口保持精简，将行为交给职责明确的模块。文件名使用简短、描述性的 lowercase 名称；值使用 camelCase，类型使用 PascalCase。

保持核心解析与执行独立于终端输出和进程控制。帮助、版本与本地化策略放在 breadc，通用转换和输入诊断放在 core。

## 实现

采用满足当前需求的直接实现，不为未确定的需求增加扩展层。修改行为时同时检查类型契约和错误路径。

技术方案应能对应到明确的用户目标，并遵守架构职责边界。内部重构不应无意改变用户行为，也不应为了保留某种实现方式而改写需求。

区分声明错误、输入错误和内部约束错误。沿用结构化错误码及诊断字段，不依赖错误文案判断行为。不要吞掉转换器、中间件或动作的异常。

注释解释约束或非显然的原因，避免复述代码。生成产物通过构建更新，不手工修改。

## 格式

Prettier 3 使用两空格缩进、单引号、分号、无尾随逗号及 120 字符 print width。

提交前运行 `pnpm format`。当前命令处理 TS、TSX、JS 和 MJS；Markdown、JSON 和 Vue 不在这个命令的匹配范围内。纯文档修改检查排版、链接及 `git diff --check` 即可。
