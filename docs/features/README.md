# 用户需求

Breadc 首先是一个用于编写 CLI 的命令行参数与选项解析框架。

- 开发者描述工具接受什么输入、需要执行什么操作；
- 使用者在终端输入命令，工具理解其中的参数和选项，完成相应任务。

这是需求的起点。命令组织、输入校验、开发提示和帮助等能力，都应服务于“让 CLI 容易编写、容易使用”这一目标。

| 需求 | 用户目标 |
| --- | --- |
| [命令组织](commands.md) | 从一个简单命令开始，逐步组织更多业务操作 |
| [命令分组](groups.md) | 按业务领域组织操作，提供共同设置和分组默认入口 |
| [参数输入](options.md) | 自然、明确地向 CLI 传递操作对象和设置 |
| [转换与校验](validation.md) | 按业务要求理解输入，并帮助用户修正错误 |
| [命令执行](execution.md) | 完成命令所代表的任务，并提供必要的反馈 |
| [开发体验](types.md) | 根据输入声明获得可靠提示，减少 CLI 编写错误 |
| [帮助与发现](help.md) | 让使用者知道命令能做什么、如何使用 |

## 示例约定

每个场景包含代码示例和使用示例。代码是 CLI 开发者编写的应用示例，不是 Breadc 内部实现。使用示例将命令与其输出放在一起，假设应用已配置为对应名称的可执行命令，代码以 TypeScript ESM 编写；不同场景独立使用。

使用示例中的结果体现终端输出、用户可观察的操作或开发时提示，不以框架函数返回值和内部执行状态作为用户目标。涉及 Zod 的示例需额外安装 Zod。
