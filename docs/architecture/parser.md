# Parser 解析规范

本文规定声明解析、argv 匹配和语法诊断。输入转换与执行见 [runtime](runtime.md)，静态类型见 [types](types.md)。以下 argv 示例均已移除可执行文件和脚本路径。

## 输入与输出

公开的 `parse(app, argv)` 接受 `string[]`，返回 `Context`。它解析声明、确定有效命令与选项、绑定原始输入并检查语法，不执行 cast、命令动作或选项动作。未知选项处理器在扫描期间执行。

每个数组元素已经是一个 shell 参数；parser 不再拆分其中的空格，不处理引号、变量或通配符展开。除布尔文本识别外，输入保留为字符串；识别负数只用于划定边界，不会转成 number。

## 声明语法

### 命令、分组与位置参数

命令 spec 由零个或多个固定名称片段，以及其后的参数声明构成，例如 `remote add <name> [url]`。固定片段按空格划分，连续空格会跳过；参数开始后不能再声明固定命令片段。`.argument()` 添加的参数接在 spec 中的参数之后。

| 位置参数 | 原始值 | 约束 |
| --- | --- | --- |
| `<name>` | `string` | 必须提供一个值 |
| `[name]` | `string \| undefined` | 可以省略 |
| `<...name>` | `string[]` | 至少一个值，必须位于参数序列末尾 |
| `[...name]` | `string[]` | 零个或多个值，必须位于参数序列末尾 |

必填参数必须位于可选参数之前，spread 最多一个；空参数名、缺失闭合括号、非法顺序属于声明错误。推荐声明使用表中的标准写法；当前运行时对可选 spread 的连续点数校验较宽，类型推导只识别 `...`，不应依赖非标准写法。

分组只包含固定名称片段，不能包含位置参数；公开 API 提供应用下的分组及分组下的命令，没有嵌套分组注册接口。多段命令路径不等于嵌套分组对象。

命令别名通过 `.alias()` 添加，只包含固定名称片段，沿用原命令的参数和选项。分组命令及其别名自动带上分组前缀。没有固定片段的根命令，或含空别名的根命令，是应用默认命令；分组中相对路径为空的命令或别名是分组默认命令。

### 选项

每个选项必须有长名称，可以有一个 ASCII 字母短别名。短别名格式固定为 `-x, --name`，长名称和值占位名由 ASCII 字母、数字和连字符构成。名称大小写敏感。

| 声明 | 形态 | 未提供时的内置原始值 |
| --- | --- | --- |
| `--flag` | 普通布尔 | `false` |
| `--no-flag` | 仅否定布尔 | `true` |
| `--[no-]flag` | 正反双形式布尔 | `false` |
| `--name <value>` | 出现时必须带值 | `undefined` |
| `--name [value]` | 出现时可以不带值 | `undefined` |
| `--name <...value>` | 数组选项，每次出现至少带一个值 | `[]` |

否定形式不能带值占位声明；选项不支持 `[...value]`。`<value>` 和 `<...value>` 约束选项出现时的值，不要求选项本身一定出现在 argv 中。

布尔三种形态共享规范名 `flag`，但只接受已声明的拼写。`--flag` 不隐式支持 `--no-flag`；`--[no-]flag` 是声明语法，不能原样用作 argv。仅否定形式的短别名同样表示取反，双形式的短别名表示正向赋值。

## Token 与取值边界

`--` 结束扫描，后续 token 原样放入 `context.remaining`，不再匹配命令、选项或位置参数，也不能用来满足必填位置参数。单独的 `-` 和空字符串是普通值。

以 `--` 开头且长度大于 2 的 token 是长选项；以单个 `-` 开头的非空后缀通常是短选项。完整匹配十进制负数语法的 token 作为普通值，包括 `-2`、`-.5`、`-2.`、`-2e-3`。`-0x10`、`-Infinity`、`-2foo` 等仍视为选项。

### 长选项和普通带值选项

长选项按第一个 `=` 分割名称和值：`--name=a=b` 的值为 `a=b`，`--name=` 的值为空字符串。附着值可以是 `--` 或看起来像选项的字符串。

非布尔选项没有附着值时，只有下一个 token 既不是 `--`、也不像选项，才会消费它。必填值缺失产生 `MISSING_OPTION_VALUE`；可选值缺失接受 `undefined`。默认值不能补救显式输入中的缺值。

### 短选项组合

短选项从左至右依当前有效声明划分：布尔选项继续扫描后续字母，第一个带值选项消费剩余后缀作为值并结束组合。紧接字母的 `=` 将其后全部内容作为该选项的值。

假设声明 `-a, --all`、`-b, --brief` 和 `-o, --output <file>`：

| argv | 匹配结果 |
| --- | --- |
| `-ab` | `all=true`、`brief=true` |
| `-ab=false` | `all=true`、`brief=false` |
| `-abofile` | `all=true`、`brief=true`、`output='file'` |
| `-abo=file` 或 `-abo file` | 同上 |
| `-oab` | `output='ab'`，不会继续解析 `a`、`b` |

遇到未知字母时，剩余后缀作为一个未知 key 处理，不再逐字母尝试，例如 `-axyz=value` 在处理 `a` 后交出 key `xyz` 和值 `value`。

### 布尔值与重复输入

布尔选项省略附着值表示 `true`；只通过附着值接受显式布尔文本，不消费下一个 token。可接受文本不区分大小写：真值为 `true/t/yes/y/on/1`，假值为 `false/f/no/n/off/0`。其他文本（包括空字符串）产生 `INVALID_BOOLEAN_OPTION_VALUE`。

否定拼写在识别文本后取反，因此 `--no-cache=false` 得到 `cache=true`。`--flag false` 则留下普通字符串 `false`。

已声明的非 spread 选项只能出现一次，短长别名及正反拼写共用次数。重复输入产生 `DUPLICATE_OPTION`，不采用“最后一次覆盖”；无效的首次输入也计入重复检测。扫描仍消费重复选项自身的值，以继续汇总后续问题。

### 数组选项

数组选项可重复出现，按输入顺序追加。使用空格取值时，消费后续所有连续普通 token，直到下一个选项、`--` 或输入结束；命令名称也可能在这里被消费。使用附着值时，本次只收集该附着值。

| argv（声明 `--include <...file>`） | 收集值 |
| --- | --- |
| `--include a b` | `['a', 'b']` |
| `--include=a --include=b` | `['a', 'b']` |
| `--include=a b` | `['a']`，`b` 留给命令/位置参数匹配 |
| `--include=` | `['']` |

收集后的值不会因参数不足或 cast 失败而重新分配给位置参数。每次出现都要有值，即使之前已有值或配置了默认数组。

## 作用域与命令匹配

全局选项首先生效；完整匹配分组后加入分组选项；提交命令匹配后加入命令选项。普通命名命令的局部选项不会提前全局生效。选项先于命令出现时使用当时的作用域，默认命令回退可以重新扫描这些 token。

同一规范长名称的后注册声明替换此前声明及其长名、否定名和短名绑定，最终只输出有效声明。替换为不同对象时不继承旧对象的显式值；同一选项对象在更窄范围复用时保留已匹配值。不同长名争用短别名时，后注册者拥有该短别名，长名称仍独立有效。

命令匹配保留已完整匹配的候选，同时尝试更长固定路径。例如同时有 `subject [name]` 和 `subject status` 时，`subject status` 优先选后者；更长路径未完成时退回较短候选，候选之后已读取的固定片段重新作为其参数。已被选项消费的值不会参与这种回退。

默认命令选择按以下顺序进行：

1. 若应用仅注册了一个命令，且它是默认命令、没有任何非空命令路径，直接在该命令范围扫描。
2. 其他情况先匹配显式命令。已有命令，或已有选项动作且扫描无诊断时，保留本轮结果。
3. 否则，已匹配分组就重扫并尝试其默认命令；没有匹配分组才尝试应用默认命令。分组没有默认命令时不会继续落到应用默认命令。
4. 回退重置匹配状态与临时诊断，只用最终轮次绑定参数、选择动作和报告输入问题。

应用默认命令不能重复；同一路径的不同命令、分组，以及匹配分组中的重复默认命令会在相应解析阶段报声明错误。相同命令对象上的重复别名不视为两个命令。

## 未知选项与参数绑定

未知选项默认产生 `UNKNOWN_OPTION`。`allowUnknownOption()` 注册默认未知选项处理器；自定义处理器通过 `allowUnknownOption(handler)` 注册，按应用、已进入的分组、已提交的命令顺序调用，首个非空结果接受输入，`null/undefined` 交给下一个。它们与 `.use()` 注册的动作中间件不同，术语见 [runtime](runtime.md#回调术语)。

未知选项处理器是同步解析扩展，参数为 `(context, key, attachedValue)`；不带附着值时，后续 token 尚未作为值交给它。当前实现仅使用返回对象的 `type` 决定取值方式（默认 `optional`），实际 key 和值仍来自原 token；返回的 `name/value` 不执行重命名或转换。每次未知选项接受都会创建匹配对象，不能套用已声明选项的重复累计规则。

回退可能再次调用未知选项处理器；此时 `context` 仍在构建中，最终 `group/command` 在扫描结束才写入。因此处理器不能假设只执行一次或读到最终匹配范围，也不应在这里触发业务动作。

最终有命令且没有选项动作时，普通值按参数序列绑定。缺少必填值产生 `MISSING_ARGUMENT`，多余值及匹配命令前未归属的普通值产生 `UNEXPECTED_ARGUMENTS`。没有命令时，未匹配普通值保存为 `arg_0` 等原始参数，不直接报未知命令错误。

有效选项动作会跳过整个位置参数绑定和数量检查，但保留全部扫描诊断；选择条件及执行规则见 [runtime](runtime.md)。

## 诊断边界

声明错误使用 `DefinitionError`。最终扫描及参数绑定的语法问题汇总为单个 `InputError`，其 `issues` 为非空列表；不执行 cast 来掩盖语法错误。普通扫描问题按发现顺序收集，参数问题随后补入。
